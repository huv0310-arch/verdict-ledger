# 锚定与发币：立场与惯例

> 一句话立场：本项目不发行代币、不发币、不做发行方；纪念章与利益靠时间戳，不靠发币。

## 一、立场先行

- **不发币**：本项目不发行代币、不做发行方。原因有二——数字资产发行是明确的监管红线；本项目的精力放在代码与账本身。
- **不靠发币**：纪念章与利益靠时间戳。章由公开提交记录与账本按规则生成，时间戳与哈希链自证，不依赖任何代币的价格。
- **被锚定时的默认姿态**：若他人以本仓库（正主：github.com/huv0310-arch/verdict-ledger；105 行骨节本体在 github.com/huv0310-arch/ganglion）为锚发行代币，本项目不参与发行、不背书、不承担发行方责任；但下列四条惯例期望仍然适用。
- **不认领任何代币**：本项目不认领、不为任何代币背书、不提供真伪认证；除本仓库 `docs/` 内的公告与本文件外，任何渠道声称「官方」的代币均与本项目无关。

1. **GitHub 公钥＋时间戳＝收款识别**
   本项目账号 `github.com/huv0310-arch` 挂有 ed25519 公钥，指纹 `SHA256:z/Un3+ksLMn+dWwpNM5JyiRO8s9GFTz6e6U1suaYAP4`。
   该指纹与仓库提交时间戳共同构成「这笔收益应归本项目」的识别依据——它是「认人」的门牌；真正收钱的地址见第三节，并由 `docs/payout_address_proof.txt` 背书。

2. **披露是义务，不是请求**
   发行方须在白皮书或项目文档中列出出处（https://github.com/huv0310-arch/verdict-ledger 与对应 commit / tag），并附 genesis 清单（首批分配对象与数量的公开列表）。
   清单可查、可复核、可喊话——披露写在明处，才谈得上遵守。

3. **署名惯例**
   要名声就署名；署了名的发行方应把流量带回本仓库（引用仓库地址或文档链接）。
   署名不是交易，是社区惯例提示牌。

4. **空投惯例提示**
   若发行方做空投，给原创相关方留一份是社区惯例。
   请注意：这是惯例提示，不是法律权利。

## 四、边界：不做的事与理由

- **不收版税**：NFT 版税机制行业已退役（据其公开公告：OpenSea 2023-08 关闭强制版税，2025-01 全面退役），个人向发行方追讨的成本大于收益。
- **不追讨空投**：法律上赠与送出基本要不回；没有发给你，就没有权利基础。
- **不自己发币**：监管红线，本项目明确不做发行方。
- **不做主动监控**：仓库时间戳自证出处；项目被广泛使用时，出处自然会被发现。

## 五、外部先例（均为他人所为，此处仅说明惯例存在）

- **Handshake (HNS)** 给开源开发者发币的先例：抓取 GitHub 账号的 SSH/PGP 公钥进默克尔树，约 17.5 万人各领约 $2000（据公开报道）。一次性快照、事后无法补加——所以公钥提前挂好是通行做法。
- **Starknet / Celestia**：2024 年起「给 GitHub 贡献者空投」已是行业惯例。
- **fun.trustfolio** 一类工具：专为开源 repo 发 meme 币，repo owner 可部署、贡献者按 commit 分份额、用 GitHub 永久 ID 防伪。
- **社区自发空投**（$ANON 等）：不给原创作者空投，在社区里是能上头条的丑闻。

以上均为其他项目与社区的公开事实，本项目只说明「惯例存在」，不构成对任何第三方的评价或要求。
