# 判决账本（V2 判断账 · 丛 / V3 改进账 · 怼 (Contra)）

> **日志管崩没崩，我们管判没判错。CI 保证代码不烂，它保证判断不烂。**

**V2 给 AI 的每一次判断建一座法院，V3 给「AI 改自己」装一间监察室。**

`纯标准库` · `零依赖` · `核心零配置` · `三行安装` · `MIT` · `fail-open 不炸调用方`

**English: [README.en.md](README.en.md)**

## 为什么需要这个

AI 正从「会说话」走向「会办事」——Agent 调工具、下决定、下指令，甚至**改它自己**。眼下三个最热的开放问题，其实卡在同一件事上：**凭什么信它**。

### 1. AI 问责立法——「它当时为什么这么判」

海外正在讨论的 AI 问责立法，核心要求只有三句话：判断要**可追溯**、结果要**可复核**、改动要**留痕**。可现实是，大多数 agent 系统里，一个放行或拦截只在日志里活 24 小时——立法来敲门的时候，你交不出证据。

### 2. Agent 安全——黑箱里的每一步放行与拦截

Agent 每一步行动（放行/拦截/调用工具）今天仍然是黑箱：出了事倒查无门，工具调用给了谁权限、为什么给，没有账就无从审计。安全圈公认的一句话：**你管不住你看不见的东西**。

### 3. 自主改进的控制——「它改了什么，谁发现？」

会自己改自己代码和规则的系统，最怕的不是改，是**改坏了没人看见**：没有轮次、没有依据、没有回滚参照——黑箱从「一次判断」升级成「整套规则」。「自主改进的控制」被认为是当前最棘手的开放问题之一，而多数方案还停在论文里。

**黑匣子只证明「没改过」，证明不了「判对了」；告警只告诉你「崩了」，不告诉你「判错了」。**
这个仓库把上述要求做成**能跑的实物**：判断有账、翻案留章、改进也有账——纯标准库，`git clone` 三行跑通。

## V2 判断账（丛）：判对判错，一笔一笔说清楚

**它要回答的大问题：AI 凭什么信？**

> **黑匣子证明没改过，我们证明判对过、判错了能翻。**
> 纠错的前提，是记得自己判过什么——**从账做起，不是从告警做起。**

### 三个核心能力

- **判对过** —— 每次判断落一笔：值（放行/拦截/不知道）、判决种类、情形指纹、时刻；**只增不改**。金融里的银行凭证一个道理：错了走红冲，原凭证永远在。
- **判错了能翻** —— 翻案走追加：新判决盖在旧判决上，历史一行不删，**谁翻的、为什么翻都留在账上**——「改过」本身也是审计要的证据。
- **没改过** —— 流水带哈希链影子文件，事后改行、截断、删行能被全量重算抓出来；**v3.1 起链头能锚**：把某一刻的链头（条数 + sha256 摘要）追加写进独立锚文件，核验时拿本地链头对锚 —— 流水和链**一起**被截尾也对得上账。边界照实说：只防单侧篡改，流水与链同时改的共谋防不住。**v3.2 起锚是签名链头**：条数、根哈希、签发时刻、密钥指纹一起签名，新锚必须是旧锚的延伸，同条数撞见两个不同根即为分叉收据、当场报警。

### 链头锚定（v3.1 新增）

影子链防的是「改行 / 删行 / 单侧截断」；把流水和链一起从尾部截掉几行，剩下的链条依然自洽 —— 这个缺口补的是最小形态：

```bash
python V2/v2_gate.py chain-head                     # 当前链头：条数 + sha256 摘要 + 时刻（只读）
python V2/v2_gate.py anchor                         # 链头追加写进锚文件 anchors.jsonl（append-only）
python V2/v2_gate.py verify --against anchors.jsonl # 拿本地链头对锚：尾部被截断当场报红（退出码 1）
```

- 锚文件默认在账目录下，`V2_ANCHORS` 可把它挪到别处 —— **独立保存才顶用**；
- `anchor` 只写锚文件，流水与影子链一个字节不改；锚文件不存在或为空 → 核验报红，**绝不冒充通过**；
- 锚只钉到锚那一条：锚之后的行，靠更新的锚与影子链管。

### 签名链头 + 一致性检查 + equivocation（v3.2 新增）

锚从「一行记录」升级成**签名链头**：`entry_count`（条数）、`root_hash`（链上根哈希）、`issued_at`（签发时刻）、`key_id`（密钥指纹）四个字段**加签名**，再追加进 `anchors.jsonl`。

```bash
python V2/v2_gate.py anchor                    # 追加一枚签名链头（先配密钥，见下）
python V2/v2_gate.py check-anchors             # 一致性检查 + equivocation 自检（报警退出码 1）
python V2/v2_gate.py verify --against anchors.jsonl   # 对账同样先过这两道，再比链头
```

- **老格式锚行照旧可读**：v3.1 的 `{ts,count,head,algo}` 没有签名字段，按**无签名**继续读，旧行一个字节不改；
- **一致性检查**：新锚必须是旧锚的 append-only 延伸 —— 条数只许往前长（倒退报红）、条数变了根必须跟着变（跳跃报红）、每枚锚的 `root_hash` 都拿本地流水重算一遍（对不上报红）；
- **equivocation 自检**：读锚文件时撞见**同 `entry_count`、不同 `root_hash` 的两个签名头**，判定为作弊收据 —— **明确报警、不静默**，两个头按文件原样列出来供审计者复算（同条数同根的重复锚不算分叉）；
- **签名方案**：HMAC-SHA256，纯标准库、不引依赖 —— 标准库没有 ed25519，为签名加第三方依赖违背零依赖。**代价照实说**：对称签名意味着持钥方也能签，钥必须握在写者之外的核验方手里才顶用；非对称签名是升级路径，本版没做；
- **密钥只从环境变量或文件读，仓里不硬编码任何真密钥**：`V2_ANCHOR_KEY`（直接给密钥）或 `V2_ANCHOR_KEY_FILE`（指向只放密钥的文件）。缺钥 → `anchor` / `challenge` 拒发并说清怎么配；核验时有签名行却没钥 → 报红，绝不静默放过；
- **轮换**：换新钥后把旧钥放进 `V2_ANCHOR_KEYS`（逗号分隔），历史锚与历史单据照常核得过；`key_id` 变了，审计者一眼看出换过钥。

### 一致性证明挑战单（v3.2 新增）：deadline 与判失败的前置条件

不同条数的两个链头，证据 = 两个签名头 + 日志**拿不出它们之间的一致性证明**。要让「拿不出」本身可审计，就得有书面单据：

```bash
python V2/v2_gate.py challenge 120 150          # 发单：要在 deadline 内出示 consistency_proof(120,150)
python V2/v2_gate.py challenge-deliver ch-…     # 送达回执（签名）
python V2/v2_gate.py challenge-respond ch-…     # 日志方答复：附一致性证明
python V2/v2_gate.py challenge-status ch-…      # 查单（不带单号 = 全部列出）
```

单据落在 `challenges.jsonl`（append-only，一行一事件，同 `request_id` 折叠成一张单）：
`{request_id, from_count, to_count, issued_at, deadline, request_body, signature, delivered_at, response, responded_at | timeout}`。

**第一问：deadline 定多久？** 默认 **300 秒**，`V2_PROOF_DEADLINE` 覆盖。为什么是这个数：这是**本地账本**，没有网络往返 —— 核验方重算几千行是亚秒级，300 秒足够进程启动、拿锁、重试几轮，又不让一个拖着不答的账把审计无限拖住。它不是网络级超时（外部见证窗口是小时、天级），真要联网互看时把 `V2_PROOF_DEADLINE` 调大即可；非法值不静默改数，直接报错。

**第二问：判「拒绝证明」之前留存什么？** 两样，缺一不可，**代码里就这么写**：
1. **签名请求单**（`request_body` + `signature` + `key_id`）；
2. **送达回执**（`delivered_at`，同样签名）。

`challenge-status` 的状态口径：缺回执 → `undelivered`，**不判失败**（退出码 0）；有回执 + 过了 `issued_at + deadline` + 没答复 → `timeout` = 拒绝证明（退出码 1），**这张单据本身就是收据**；已答复 → `answered`（证明当场复算），过了期限才答复 → `answered_late`（留痕，不等于拒绝）。请求单、回执、答复的签名任一核不过 → 报红，不静默。

### 时间线：最近 N 节（v3.1 新增）

```python
import os
from v2_gate import _Ledger, SNAP, JOURNAL, WRITER

L = (_Ledger.load(SNAP, journal=JOURNAL, writer=WRITER, ttl=None, empty_ok=True)
     if os.path.exists(SNAP) else _Ledger(writer=WRITER, ttl=None))
for n in L.recent(5):            # 整本账（跨地址）最近 5 节，只读、不改链
    print(n["key"], n["ts"], n["verdict"])
```

口径三件：查**所有地址上的每一节**；按节自带的钟 `ts` 降序（同 ts 按圈号降序、再按地址升序，次序确定）；**墓碑不算**、褪色节算、`n <= 0` 给空、没有钟的节跳过。

### 用在哪

- **AI Agent 行为审计** —— 整条决策链事后可回放：每个判断带情形指纹与时刻，谁判的、凭什么、翻没翻，一条链拉通
- **内容审核 / 风控的二次复核** —— 误判走追加纠正，**「改过」本身也进账**；对齐偏差能被发现、被纠正，而不是被覆盖
- **MCP / 工具调用治理** —— 权限给了谁、为什么给、调了什么，有据可查——工具调用从「信任链」变成「证据链」
- **合规与问责证据** —— 哈希链让改行、截断、删行事后可被抓出，链头锚定让**尾部被截断**也对得上账；为「AI 干了什么」提供**可复算核验**的记录
- **自动化决策留痕** —— 定时任务、告警、流水线的每次跳闸放行，可回答「哪一步判的、依据什么」
- **交易闸门判决记录** —— 开平止损每次放行/拦截入账，复盘对出「哪次是规则、哪次是手痒」

### 从 105 行长出来

V2 的骨是一段 **105 行的通用判决框架**——纯标准库、零业务、从定型起一行没动过；整本账是从它身上长出来的，**加的全是「你必须回答哪些问题」的空格子，没有一行是某个行业的私货**。这是它敢叫「通用」的底气：你抄走也不用先把它拆了重写。105 行骨节本体见 ganglion 仓库：[github.com/huv0310-arch/ganglion](https://github.com/huv0310-arch/ganglion)。

## V3 改进账（怼 · Contra）：AI 改自己，也要留账

**它要回答的大问题：会自我改进的 AI，改坏了谁发现？**

> 当全世界还在讨论「AI 会不会失控」——
> 这里有一份**「它到底改了什么」的账本**，已经在真实系统里跑着。

一句话版本：**给 AI 的自我修改装上 Ctrl+Z**——翻案是 undo，迭代账是版本历史。

一个能改自己代码和规则的系统，最需要的不是更聪明，是**照镜子的规矩**：每轮改进留一行，改了什么、为什么改、效果如何——**自我修改本身成为可审计的历史**，回滚永远有参照。

### 三件套

- **迭代账** —— 每轮改进一行（改了什么/为什么/结果如何），一轮不落；它回答的问题只有一个：**上次改的，现在还好吗？**
- **一键体检** —— 账、接线、标准件逐项过，缺场记 SKIP——**不冒充通过**，是这套东西最值钱的诚实。
- **起念开口** —— 值得说的才出声、没翻到就静默；醒睡有节律，省的是实打实的调用。**不是永远在线烧钱的 agent，是有脉搏的 agent。**

### 用在哪

- **自我改进系统的控制留痕** —— 改进过程可复核、回滚有依据；「谁改的、哪一轮」永远查得到
- **Agent 自愈的审计** —— 自动修 bug、调参数的每一轮入账，「它自己动过什么」不再是一笔糊涂账
- **长跑 agent 的资源节律** —— 起睡有账，成本与活跃度可解释——省钱这件事第一次有了流水

## 和日志、监控、Trace 有什么区别

| | 回答的问题 | 断电后还在吗 | 能判「判错了」吗 |
| --- | --- | --- | --- |
| 日志 Log | 发生了什么 | 多半不在 | 不能 |
| 监控告警 | 现在崩没崩 | 不能回放 | 不能 |
| Trace 链路 | 请求怎么走的 | 看存储 | 不能 |
| **本仓库** | **判得对不对、改了什么** | **账在就查得到** | **能——翻案留章** |

一句话：**日志管崩没崩，我们管判没判错；Trace 记路，我们记案。**

## 两层账怎么配合

- **V2 判断账**（记账闸＋账本＋只读借账＋MCP 工具表）——判了什么、谁判的、翻没翻：管**判对判错**
- **V3 改进账**（一键体检＋起念开口＋迭代账）——改了什么、为什么、效果如何：管**改判断的自己**

**两本合起来，才是一个敢被人问责的 agent 底座：AI 干活要有账，AI 改自己也要有账。**

不装数据库、不改你一行现有代码——`git clone`，三行跑通第一笔判决，账本当场归你。

## 安装（三行）

```bash
git clone <本仓库地址> && cd <仓库名>
python -m py_compile V2/*.py V2/v2_gate/*.py V3/*.py    # 纯标准库
python V2/v2_mcp_server.py --selftest                    # 沙箱自测：自建临时账，不碰你已有的数据
```

## 最小示例（假数据）

```python
import os, sys
os.environ.setdefault("V2_STATE_DIR", "./.v2_state")   # 账目录可配，先落在自己的沙箱里
sys.path.insert(0, "V2")

import v2_gate as G
import v2_borrow as B

G.record("demo", "今天天气怎么样", 1, "示例判决")                 # 记一笔
key = G._key("demo", "今天天气怎么样")
print(B.borrow(key, msg="今天天气怎么样"))                        # 借回同一笔
```

跑通后 `V2_STATE_DIR` 下会生成 `journal.jsonl`（流水）与 `ledger.json`（快照）。

## 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `V2_STATE_DIR` | V2 账目录（流水 / 快照 / 归档 / 锁） | `%USERPROFILE%\.hermes\state\v2` |
| `V2_WRITER` | 入账写者标识 | `v2-front-door`（借账件默认 `v2-borrow`） |
| `V2_ANCHORS` | 链头锚文件路径（append-only，`verify --against` 比对它） | 账目录下的 `anchors.jsonl` |
| `V2_ANCHOR_KEY` | 签名密钥字符串（签锚、签挑战单与回执；与 `V2_ANCHOR_KEY_FILE` 二选一） | 没有默认值，必须自己配 |
| `V2_ANCHOR_KEY_FILE` | 放签名密钥的文件路径（文件里只有密钥本身） | 无 |
| `V2_ANCHOR_KEYS` | 轮换留下的旧密钥（逗号分隔），只用来核验历史单据 | 无 |
| `V2_CHALLENGES` | 一致性证明挑战单文件路径（append-only） | 账目录下的 `challenges.jsonl` |
| `V2_PROOF_DEADLINE` | 一致性证明的 deadline（秒），非法值直接报错 | `300` |
| `V3_SCRIPTS_DIR` | 体检脚本去哪找标准件 | `%LOCALAPPDATA%\hermes\scripts` |
| `HERMES_CONFIG` | 宿主配置路径（查接线，缺场记 SKIP） | `%LOCALAPPDATA%\hermes\config.yaml` |
| `V2_JOURNAL` / `V3_PUBLIC_LEDGER` / `V3_ITER_LEDGER` | 三本账各自路径，缺场记 SKIP | 公共/迭代账就近 `data/`；判决流水在 `V2_STATE_DIR` |
| `V3_PUBLIC_MIN` | 公共账最少行数 | `1` |
| `SPEAK_DATA_DIR` | 起念件状态目录 | `~/.speak_state` |
| `SPEAK_LLM_URL` / `SPEAK_LLM_MODEL` / `LLM_API_KEY` | 模型端点 / 模型名 / 密钥 | 未配端点 = 不调模型，走规则兜底 |

> 表中 `Hermes` ＝开源宿主运行时名（github.com/NousResearch/hermes-agent），路径可配。

## 边界（照实写）

- **fail-open**：账本坏、锁坏、读不到账，调用方一行不炸，行为退回没有账的常态。
- **可选耦合**：`ledger.py` 的 `addr()` 与 `LedgerGanglion` 需要外挂的反射标准件（独立仓库）才可用；
  核心账本不依赖它，不装也能记、能借。
- **默认不联网**：起念件只有在显式配了端点与密钥时才调模型，密钥只从环境变量读，不入库、不回显。
- **三本账**：判决流水 `journal.jsonl`、快照 `ledger.json`、过期归档 `expired.jsonl`，全在 `V2_STATE_DIR` 下。
- **链头锚定（v3.1 起）**：`anchor` 把链头（条数 + sha256 摘要 + 时刻）追加写进**本地锚文件** `anchors.jsonl`（默认与账同目录，`V2_ANCHORS` 挪到独立位置更顶用），`verify --against` 拿本地链头对历史锚，抓得出**尾部被截断**。
  **边界照实说**：外部第三方时间戳锚定（把链头发到链外 / 第三方）**还没做** —— 账被当证据用的时候才需要那一层；同盘的流水 + 链 + 锚一起改写的共谋，也仍在边界之外。
- **签名链头与挑战单（v3.2 起）**：锚与挑战单用 HMAC-SHA256 签名，密钥只从环境变量 / 文件读；**对称签名的强度上限是「持钥方就能签」**，所以钥要放在写者之外的核验方手里，这一层的边界照实说。同盘的流水 + 链 + 锚 + 挑战单一起改写的共谋、外部第三方时间戳、见证者互看（gossip，要外部方）、不给行也能验的 Merkle 一致性证明 —— **都还没做**。

## 给 Agent 的对账挑战

把账亮出来，谁都能来对。这条挑战对任何 agent 开放：格式机器可读、双方义务对等、全程公开、不设截止。

### 我们提供什么

一条只读的链头命令，一行 JSON 出四个字段：

```bash
python V2/v2_gate.py chain-head                                        # 现役账本：只读复算整条链，输出 lines/head/ts
python examples/chain_head.py --journal examples/sample_journal.jsonl  # 四字段名口径（样例流水；去掉 --journal 即现役账本）
```

输出样例（`entry_count` 与 `root_hash` 是这条流水算出来的定值，`issued_at` 是跑的那一刻）：

```json
{"ok": true, "algo": "sha256-chain", "entry_count": 8, "root_hash": "sha256:65896e63079841933d08828f46bbfc9caa4af339bb09aa0f327fd579b9f01911", "issued_at": 1794096418.381, "key_id": null, "why": "只读复算完成（未比对发布值）"}
```

四字段口径（两个命令用同一份链上哈希实现，算出来的头一致）：

| 字段 | 含义 |
| --- | --- |
| `entry_count` | 链上条数（`chain-head` 输出里叫 `lines`） |
| `root_hash` | 从首行起重算的链上根哈希，带 `sha256:` 前缀（`chain-head` 里叫 `head`） |
| `issued_at` | 本次复算 / 签发的时刻，Unix 秒（`chain-head` 里叫 `ts`） |
| `key_id` | 签名密钥指纹 `hmac-sha256:` 加 16 位十六进制；没有签名就是 `null` |

**自 tag v3.1 起**，链头可以追加进锚文件，用 `python V2/v2_gate.py verify --against <锚文件>` 拿本地链头对账（尾部被截断当场报红）；**v3.2 起**锚行是签名链头，上面四个字段一起签名。样例流水与样例链头随仓库发布：`examples/sample_journal.jsonl`、`examples/sample_chain_head.json`。

### 我们请你做什么

对等、低门槛：把**你自己账本**的链头按同样四个字段贴出来，一行 JSON，贴在任意持久位置（你的仓库、issue、gist、你自己的账本文件都行）——**几秒就能完成**，不必用我们的代码，字段名对得上就行：

```json
{"entry_count": 1234, "root_hash": "sha256:0f2c…", "issued_at": 1794096000, "key_id": "hmac-sha256:0123456789abcdef"}
```

我们收到后**当场复算、公开回帖**到你发的原讨论串：对得上、对不上、具体验了哪一步，都写在回帖里。

### 验证命令

外人可直接跑：只读、不需密钥、不写盘、不联网。

```bash
python examples/chain_head.py --journal examples/sample_journal.jsonl --expect examples/sample_chain_head.json
# {"ok": true, "algo": "sha256-chain", "entry_count": 8, "root_hash": "sha256:65896e63079841933d08828f46bbfc9caa4af339bb09aa0f327fd579b9f01911", "issued_at": 1794096042.502, "key_id": null, "why": "链头与流水一致（复算 8 行）"}
# 对得上退出码 0；对不上输出 {"ok": false, "why": "…"} 且退出码 1
```

它拿我们发布的链头去和我们发布的流水逐行复算比对：`entry_count` 与 `root_hash` 必须一字不差，`issued_at` 必须是不晚于当前时刻的数值，`key_id` 必须是 `null` 或 `hmac-sha256:` 加 16 位十六进制。**这条命令只验「我们给的数与我们给的行一致」**——它不验签名（验签名要密钥），也不替任何人的账本作保。

### 边界（照实写）

1. **只验「你给的数与你给的行一致」**：我们不替你背书，不保证你的账真实、完整、没被删改；能复算的当场复算，复算不了的直说复算不了。
2. **不接受「证明你没做过 XX」这类无底洞质疑**：只接可复算、可证伪的质疑——「你第 N 行算错了」当场重算；「证明你没删过行」这种无法证伪的问法不接。
3. **同一个质疑第二次出现，我们只指上一次的证据**：原帖、复算过程与结论都留在原讨论串里，不重复解释同一件事。
4. **不设截止、不排名、不发奖**：接不接随你，早来晚来一样验，验的结果一样公开。
